# 최초 질문과 역할 설정

## 먼저 확인

PROJECT_CONFIG.yaml의 mode·활성 역할을 확인한다.
개인 설정이 없거나 다른 사용자가 사용할 때는 반드시 아래 질문을 한다.
작성자·과거 대화에 나온 PM 직함만으로 현재 참가자 역할을 채우지 않는다.
공통 지침·빈 양식 정비를 직접 요청받은 준비 작업은 실제 참가자 역할을 만들지 않고 수행할 수 있다.

## 공통 질문: 한 번에 네 가지

1. 팀에서 사용할 이름 또는 식별명은 무엇인가요? 실명일 필요는 없습니다.
2. 담당 역할과 겸임 역할은 무엇인가요? 활성 역할 안에서 선택해주세요.
3. 배정받은 세부 업무는 무엇인가요? 개발은 기술 영역과 담당 기능을 함께 적고, 미정이면 미정이라고 답해주세요.
4. 지금 시작할 작업은 무엇인가요? 역할 설정만, 자료 검토, 기획, 디자인, 특정 기능 구현 등을 구분해주세요.

기존 담당표가 읽히면 본인의 배정인지 확인하고 이미 확인된 내용을 다시 입력시키지 않는다.
기술 스택·현재 도구·원본 링크는 문서와 환경에서 먼저 확인하며 부족한 것만 묻는다.
역할은 PM·Design·Coding·Medical이고 Plan은 공통 자료 공간이다.
템플릿 보관본의 선택 역할은 활성화 결정 전 실제 담당으로 배정하지 않는다.

## 역할별 추가 질문: 빠진 정보만

| 역할 | 추가 확인 |
|---|---|
| PM | 기획·일정·배분·발표 중 범위, 공동 담당 여부, 결정·검토를 함께할 사람 |
| Design | 담당 기능·화면, 와이어프레임·시각 디자인·프로토타입 중 단계, 개발 인계 상대 |
| Coding | FE·BE·DB·통합 중 기술 영역, 기능, 수정할 코드 영역, 연결 상대 |
| Medical | 검토할 주제·기능, 조사·검토할 수 있는 범위, 필요한 산출물·추가 확인 대상 |

실제 경로는 저장소를 확인한 뒤 담당과 연결한다. 존재하지 않는 코드를 이미 있는 것으로 쓰지 않는다.
검토자·통합 담당이 없으면 개인이 임의 지정하지 않고 PM이 조정할 항목으로 남긴다.

## 답변 이후

- 역할 미정: 공통 안내·역할 설명·질문 정리.
- 역할 확인, 업무 미정: 필요한 자료 읽기·업무 분해안·배정안 제안.
- 담당 확정: 요청받은 범위의 작성·구현·검증.
미정을 사실처럼 채우지 않는다. 독립적으로 가능한 준비는 계속한다.
답변 확인 후 [개인 양식](ROLE_PROFILE.example.yaml)에서 .local/role.yaml을 만든다.
profile_status는 unconfigured / role_confirmed_scope_pending / assigned 중 실제 상태를 기록한다.
allowed_edit_paths는 팀 배정·구체적 요청에 맞는 범위이며 이 값 자체가 권한을 만들어내지 않는다.

## 다음 대화와 역할 변경

같은 사용자의 새 대화에서는 저장된 역할·현재 작업을 짧게 표시하고 변경된 정보만 묻는다.
다른 사용자이거나 담당표·요청과 충돌하면 해당 항목을 다시 확인한다.
역할 변경 시 진행 중 작업·미검증·연결 상대를 인계하고 담당표와 개인 설정을 함께 갱신한다.
하나의 폴더를 여러 사람이 공유한다면 프로필을 사람별로 구분해 선택해야 한다.
기본 운영은 각자 별도 작업 사본을 사용하는 것이다.
