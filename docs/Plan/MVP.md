## 너빼고다옴 — MVP 확정 정책

<b>문서 버전: PM-MVP-v2.0</b><br />작성 기준: <date start="2026-11-14" /><br />팀 논의: <mention url="https://app.notion.com/p/418c0efa070a80528399fa6d71ce5b1c">Medilux X ITTA X UMC Half Hackerton 3Team - 너빼고다옴</mention>

<b>핵심 방향:</b> 아직 모두 모이지 않은 시간에도 다음 장소와 활동을 함께 정한다. 이동 중에도 의견을 낼 수 있는 참가자가 같은 모임에 참여하며, 정확히 10분에 한정하지 않는다.

사용자가 전체 추천안 21개를 승인한 기획 기준이다. 서비스명은 너빼고다옴, 지도는 카카오지도 API로 확정했다. 와이어프레임 제작은 후속 요청으로 이번 작업에서 제외했다. 제품 구현·실연동·시연 완료를 의미하지 않는다.

<b>제공 형태 — 확정:</b> 모바일 우선 반응형 웹앱. 카카오지도 JavaScript API를 사용한다. 프레임워크·배포 환경·개인별 개발 담당·실제 지원 기기는 기술 인계 시 확정한다.

### 1. 대상 사용자와 가치

- <b>주요 사용자:</b> 친구들과 모임을 주도하는 사람.
- <b>함께 참여하는 사용자:</b> 먼저 도착한 친구와 아직 이동 중이지만 의견을 낼 수 있는 친구.
- <b>문제 가설:</b> 인원이 다 모이지 않으면 주도자가 위치·의견을 따로 확인하면서 다음 행동을 조정해야 하고, 그 사이 시간이 붕 뜬다.
- <b>제공할 가치:</b> 현장과 원격 참가자가 함께 장소·활동을 결정하고 같은 결과를 확인한다. 게임은 공백 시간에 함께 참여하는 놀이로 연결한다.
- 실제 절약 시간·사용 의사·시장 차별성은 아직 검증하지 않았다.

카카오지도는 지도·마커·최초 약속 좌표와 직선 거리 표시를 위한 선택이다. 경로·내비게이션·도착 예상 시간·자동 장소 추천은 제외한다. GPS 권한 없이도 후보·투표에 참여한다. 실제 GPS는 브라우저 위치 API에서 얻고 카카오지도에 표시한다.

기능별 구현 순서는 공동 결정 흐름을 우선 연결한다. F-008 안에서는 화면 내 안내부터 구현하고 웹 푸시는 후순위로 진행한다. 후순위는 제외를 뜻하지 않으며 미구현 기능은 인계·시연에서 구분한다.

### 3. 사용자 흐름

<b>공동 결정</b>

1. 주최자가 약속 장소·날짜·시간을 정해 모임을 만들고 초대 링크를 공유한다.
2. 친구들이 닉네임으로 참여하고, 위치 공유 여부와 자신의 도착 상태를 확인한다.
3. 모임 당일에는 위치 공유를 허용한 참가자의 위치와 약속 장소까지의 직선 거리를 본다. 약속 장소 기준 100m 이내·오차 추정치 50m 이하의 새 측정이 2회 연속 확인되면 GPS 갱신·전송을 중단하고 지도 마커를 숨긴다. 참가자 목록에는 ‘장소 근처 · GPS 꺼짐’을 표시하며, 주최자가 도착 관리 메뉴에서 실제 도착 여부를 판단한다.
4. 먼저 온 사람과 이동 중인 사람 모두 후보를 제안하고 투표한다. 이 과정에서도 화면 안의 남은 시간·안내를 확인하며 다음 행동을 준비한다. 앱 밖 웹 푸시는 후순위로 구현한다. 알림은 3-3절 확정 정책을 적용한다.
5. 주최자가 최종 장소와 활동을 확정한다.
6. 모든 참가자가 같은 결과를 확인하고 다음 행동을 준비한다.

<b>게임</b>

모임 화면 → 지각비·게임 규칙 확인 → 지각자와 도착자 전원 참여 → 점수 제출 → 평균 비교·지각비 결과 확인 → 모임 화면 복귀.

- 게임은 모임 화면에서 선택해 참여하는 흐름으로 둔다.
- 게임 중에도 장소 결정 결과를 확인할 수 있다.
- 게임에 참여하지 않거나 게임이 미완료여도 공동 결정 흐름은 계속된다.
- 게임 승패로 장소 선택권이나 1인 1표의 투표 가중치를 바꾸지 않는다.

### 3-1. 최종 확정과 GPS 운영 기준

<b>POL-DECISION-001 · 공동 결정 — 확정</b>

- 누구나 장소명＋활동명으로 후보를 등록한다. 지도 링크는 선택이며 자동 추천은 제외한다.
- 작성자는 최종 확정 전, 표를 받은 이력이 없는 본인 후보만 수정·삭제한다.
- 1인 1표이며 확정 전 변경 가능하다. 참가자 식별과 투표 중복 방지는 개발 계약에 포함한다.
- 주최자는 투표 현황을 보고 후보 한 건을 직접 확정한다. 동률·미응답·0표여도 확정 가능하며 해당 상태를 확인하고 결정한다.
- 확정 후 후보·투표는 잠금이다. 재투표·여러 안건 동시 진행은 이번 MVP에서 제외한다. 후보가 없으면 확정할 수 없다.

<b>POL-GPS-001 · 시작·기준 장소·100m 반경 — 확정</b>

- 최초 약속 장소의 좌표가 거리·반경 판정 기준이다. 다음 장소 확정으로 GPS 기준을 바꾸지 않는다.
- 첫 초대 참가자 입장 후 최초 약속 장소·일시는 잠근다. 주최자의 실제 도착 시각 정정은 이 잠금과 별개다.
- 모임 당일 한국 시각 00:00부터, 주최자 모임 종료 또는 다음 날 00:00 중 빠른 시점까지 운영한다. 페이지가 열려 있고 위치 공유를 허용한 동안만 수집·전송한다.
- 위치 전송은 10초 간격이다. 좌표 오차 추정치가 50m 이하이고 최초 약속 장소에서 직선 거리 100m 이내인 유효 측정을 2회 연속 확인하면 해당 참가자의 위치 갱신·전송을 중단한다. 같은 측정값을 재사용해 2회로 세지 않는다.
- 100m 밖·오차 기준 초과·측정 실패·오래된 측정은 연속 판정에 포함하지 않고 연속 횟수를 초기화한다. 기기별 실제 정확도는 별도 검증 후 필요한 조정을 합의한다.
- GPS 비활성화 시 개인 마커를 숨기고 참가자 목록에 ‘장소 근처 · GPS 꺼짐’을 표시한다. 그 모임에서는 재활성화하지 않는다. 휴대폰 전체 GPS 설정을 끄는 기능은 아니다.
- GPS가 꺼져도 실제 도착을 자동 확정하지 않는다. 위치 공유 여부와 관계없이 주최자가 도착 메뉴에서 확인한다.
- 권한 거부는 ‘위치 미공유’, 갱신 중단은 ‘갱신 중단’으로 표시한다. 1분 이상 새 좌표가 없으면 ‘오래된 위치’와 마지막 갱신 시각을 표시하고 실시간 위치로 취급하지 않는다.
- 페이지 종료는 다른 기기에 즉시 확정 통보할 수 있다고 가정하지 않는다. 서버에서 새 좌표가 없는 시간을 기준으로 오래된 위치를 표시한다. 닫힌 페이지의 지속 GPS 추적은 제외한다.

<b>개발 참고 · 실제 연동 미검증</b>

카카오지도 JavaScript API는 앱의 JavaScript 키와 등록 도메인이 필요하다. 약속 장소의 이름과 실제 선택한 위도·경도를 함께 저장해야 하며 장소명만으로 100m를 판정하지 않는다. 키 발급·도메인 등록·지도 로딩 성공은 아직 확인하지 않았다. [카카오지도 공식 가이드](https://apis.map.kakao.com/web/guide/), [카카오지도 API 문서](https://apis.map.kakao.com/web/documentation/).

브라우저 위치 조회에는 권한과 보안 환경이 필요하다. 오차 추정치를 함께 받고 위치 감시를 해제할 수 있다. 50m·2회·10초는 팀이 승인한 정책값이며 정확도 보증이 아니다. [위치 정확도](https://developer.mozilla.org/en-US/docs/Web/API/GeolocationCoordinates/accuracy), [위치 조회](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/watchPosition), [감시 중단](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/clearWatch).

### 3-2. 주최자 도착 관리

<b>POL-ARRIVAL-001 · 도착 판단과 표시 — 확정</b>

주최자 메뉴에 참가자·GPS 상태·도착 여부·자동 확인 시각·수정 가능한 실제 도착 시각·지각 시간을 표시한다. ‘장소 근처 · GPS 꺼짐’만으로 도착을 확정하지 않는다. 참가자는 자신의 GPS 상태로 도착을 임의 확정할 수 없다.

<b>POL-ARRIVAL-002 · 기록·정정·게임 결과 — 확정</b>

- 도착 확인 시 확인 시각을 자동 기록하고 실제 도착 시각의 초기값으로 사용한다. 자동 기록과 주최자가 수정하는 실제 도착 시각을 구분한다.
- 지각 시간은 <code>max(0, 실제 도착 시각 − 약속 시각)</code>이다. 수정 시 즉시 다시 계산한다.
- 유예시간 없이 약속 시각을 넘으면 지각이다. 내부 계산은 초 단위이며 화면은 분 단위, 1분 미만의 양수는 ‘1분 미만’으로 표시한다. 표시를 반올림해 지각 여부를 바꾸지 않는다.
- 약속 전·정각 도착은 지각 시간 0이다. 미확인 참가자는 ‘약속 시각 경과’와 진행 중인 시간을 보여주며 확정 지각 시간과 구분한다.
- 예: 약속보다 8분 뒤 도착 확인 → 지각 8분. 실제 도착을 약속보다 5분 뒤로 수정 → 지각 5분.
- 게임 후에도 실제 도착 시각 정정이 가능하다. 정시 도착으로 바뀌면 적용 지각비는 0이다. 여전히 지각이면 기존 승패 배수를 유지한다. 경기 원래 점수·명단은 소급 변경하지 않는다.
- 도착 확인 취소는 해당 참가자가 포함된 경기가 시작되기 전까지만 허용한다. 시작 후에는 확인 상태를 취소하지 않고 실제 도착 시각 정정으로 처리한다.
- 미래 시각이나 해석할 수 없는 날짜를 실제 도착으로 저장하지 않도록 입력 검증한다. 시간대는 Asia/Seoul로 표시하고 저장·서버 간 시각 기준은 개발 계약에서 일관되게 맞춘다.

### 3-3. 약속까지 남은 시간·참여 안내

<b>POL-TIME-001 · 안내 범위·구현 순서 — 확정</b>

- 약속까지 남은 시간을 후보 제안·투표·다음 행동 준비와 연결한다. Duolingo의 남은 시간 알림은 사용자가 든 표현 방식의 참고다.
- 화면 내 남은 시간 표시·안내를 먼저 구현하고 앱 밖 웹 푸시를 후순위로 구현한다. 두 채널 모두 범위에 포함하며 후순위를 제외로 취급하지 않는다.
- 약속 시각이 시간 안내 기준이다. GPS 거리로 도착 예상 시간을 계산하거나 약속 시각에 투표를 자동 종료하지 않는다.
- 약속 30분 전·10분 전·정각에 각각 1회 안내한다. 늦은 접속·모임 생성 때문에 이미 지난 알림을 몰아서 보내지 않는다.
- 최초 후보 등록 시 미투표자에게 참여 안내, 최종 확정 시 전원에게 결과 안내를 제공한다. 투표한 사람에게 이미 끝낸 행동을 재촉하지 않는다.
- 모임 종료 후 안내 발송을 중단한다. 사용자별 동일 이벤트·시각 알림은 중복 전달하지 않도록 처리한다. 화면 내 시간 표시는 각 알림 횟수와 별개로 갱신한다.
- 도착 전에는 ‘약속까지 20분 · 다음 장소에 투표해보세요’, 먼저 도착한 사람에게는 ‘모임 시작까지 12분 · 다음 활동을 정해볼까요?’처럼 상황을 구분한다.
- 약속 시각 경과·도착 미확인은 ‘약속 시각이 5분 지났어요 · 도착 확인 대기’, 도착 확인 후에는 실제 도착 기준의 고정된 지각 시간을 표시한다.

<b>웹 푸시 개발 참고 · 실제 수신 미검증</b>

표준 Push API의 구독·서버 전송·서비스 워커 수신 처리를 연결한다. 화면 안 타이머만으로 앱 밖 푸시가 완성되는 것은 아니다. iPhone·iPad는 홈 화면에 추가한 웹앱에서 사용자 동작으로 알림 허용을 요청한다. 미지원·권한 거부 시 화면 내 안내와 투표를 이용할 수 있게 한다. 실제 시연 기기·OS·브라우저에서 검증한다. 푸시 지원이 닫힌 페이지의 GPS 추적을 보장하지 않는다. [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API), [Apple 웹 푸시](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers), [WebKit 지원 조건](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

### 4. 게임 정책 — 확정

<b>POL-GAME-001 · 참여와 비교</b>

- Chrome T-Rex처럼 장애물을 피하며 점수를 얻는 방식이다.
- 지각자와 도착자 전원이 참여한다.
- 지각자의 점수를 도착자 전원의 평균 점수와 비교한다.
- 도착자 평균에는 지각자 자신의 점수를 포함하지 않는다.

<b>POL-GAME-002 · 지각비</b>

사전에 설정한 기본 지각비를 P, 지각자 점수를 S, 도착자 평균 점수를 A라고 한다.

| 조건 | 판정 | 적용 지각비 |
| --- | --- | --- |
| S가 A보다 높음 | 지각자 승리 | 0 — 면제 |
| S가 A보다 낮음 | 지각자 패배 | 2P — 기본 지각비의 2배 |
| S와 A가 같음 | 무승부 | P — 기본 지각비 유지 |

기본 지각비의 실제 금액은 모임에서 사전에 설정하며, 이 문서에서 기본 금액을 임의로 정하지 않는다.

<b>계산 예시 — 기본 금액을 지정하는 예시가 아님</b>

P가 3,000원이고 도착자 점수가 100·200·300점이면 평균은 200점이다.

| 지각자 점수 | 판정 | 적용 지각비 |
| --- | --- | --- |
| 250 | 승리 | 0원 |
| 150 | 패배 | 6,000원 |
| 200 | 무승부 | 3,000원 |

<b>계산 시 지킬 기준</b>

- 도착자가 N명이고 점수 합이 T라면 평균은 T/N이다. N은 1 이상이어야 한다.
- 평균 표시를 반올림한 값으로 승패를 바꾸지 않는다. 정수 점수라면 S×N과 T를 비교하는 방식으로 같은 판정을 낼 수 있다.
- 필요한 점수가 빠져 있으면 승패를 임의 생성하거나 누락자를 평균에서 제외하지 않는다. 아래 경기 운영 기준에 따라 무효 처리한다.
- 결과 반영은 한 경기당 한 번만 처리하며 새로고침이나 중복 제출로 금액을 중복 변경하지 않는다.
- GPS 비활성화만으로 지각 여부를 판정하지 않는다. POL-ARRIVAL-002의 실제 도착 시각을 적용한다.

<b>POL-GAME-003 · 경기 운영 — 확정</b>

- 실제 도착을 확인한 지각자에 대해 주최자가 시작한다. 지각자별 1회이며 재도전은 없다.
- 시작 시점에 선택한 지각자를 제외한 도착 확인된 전원을 비교 그룹으로 고정한다. 다른 사람도 지각했는지와 무관하게 도착 그룹에 포함하며, 경기 도중 합류자는 그 경기에 추가하지 않는다.
- 여러 지각자는 각자 한 경기를 진행한다. 각 경기의 고정 명단·평균을 사용하므로 서로 다른 경기의 평균을 섞지 않는다.
- 같은 난이도·장애물 조건, 최대 60초, 충돌 시 종료한다. 생존 시간에 따른 정밀 점수로 비교하며 표시용 반올림 값은 판정에 쓰지 않는다. 탭·스페이스로 점프한다.
- 시작 후 90초까지 필요한 점수가 모두 제출되지 않으면 경기 무효·기본 지각비 P를 유지한다. 중단·모임 종료로 미완료된 경기도 무효이며 재도전하지 않는다.
- 비교 그룹 0명일 때는 유효한 평균을 만들 수 없으므로 경기를 시작하지 않고 ‘대결 상대 없음·기본 지각비 유지’를 표시한다. 이는 재도전 횟수 소모가 아니다.
- P는 모임 생성 시 설정하는 고정 금액이며 기본값은 0원이다. 분당 가산은 없고 결과 기록만 제공한다. 실제 결제·자동 징수는 제외한다. 정시로 정정된 참가자의 적용 지각비는 경기 결과와 관계없이 0이다.

### 6. 검증 범위와 시연 기준

이번 검증 대상은 확정 정책·상태 전이·계산 예시·문서와 설정·원본과 백업의 일치다. 실제 웹앱 코드가 없어 카카오지도 로딩·GPS 실기기·웹 푸시·다중 사용자 동작은 실행하지 않았다. 아래는 구현 후 확인할 시연 체크리스트이며 문서 검토 PASS와 구분한다.

- [ ] 서로 다른 기기에서 같은 모임 입장, 최초 약속 좌표·시각·P 공유.
- [ ] 첫 참가자 입장 후 최초 약속 잠금, 후보 필수 입력·수정 권한·득표 잠금 확인.
- [ ] 투표 변경 시 중복 집계 없음, 동률·미응답·0표에서 주최자 확정, 확정 후 잠금.
- [ ] 카카오지도 키·등록 도메인·실제 지도 로딩 및 최초 장소 기준 직선 거리 확인.
- [ ] 100m·50m 경계와 서로 다른 유효 측정 2회, 오래된 좌표·오차 초과·재활성화 금지 확인.
- [ ] GPS 미공유·중단·오래됨·근처 상태 구분, GPS와 도착 상태 독립.
- [ ] 주최자 도착 확인·시각 정정·정시/지각 경계·게임 후 정산값·확인 취소 제한 검증.
- [ ] 30분 전·10분 전·정각, 최초 후보·최종 결정 알림의 대상·중복·지난 알림·모임 종료 처리.
- [ ] 웹 푸시 미허용·미지원에서도 화면 내 안내·투표, 지원 기기에서 앱 밖 알림 실제 수신.
- [ ] 경기 명단 고정·60초 종료·90초 제출 기한·누락 무효·상대 0명·여러 지각자·재도전 금지.
- [ ] 승리 0·패배 2P·무승부 P, 정확한 평균·중복 제출·P=0·도착 시각 정정 검증.
- [ ] 게임 미완료와 위치 미공유가 공동 결정 흐름을 막지 않음.

개발 기술 계약과 개인별 편집 범위는 위 역할 책임만으로 자동 배정하지 않는다. 디자이너에게 GitHub 사용을 요구하지 않는다. 기존 화면 ID S-001\~S-004는 기능 연결용이며 와이어프레임·Figma·SVG·PDF가 제작됐다는 뜻이 아니다.

행사 작업 시간은 사용자가 전달한 10:30\~14:30이다. 제출물은 핵심 타겟·사용자, 문제 정의·솔루션, MVP 설명을 포함한 피칭 PPT다. PM 평가표는 문제·타겟 7점, 적합성·차별성 8점, MVP 5점, 사업성·성장 5점으로 전달받았다. 원문 ‘8번’은 8점으로 잠정 해석했으며 정확한 발표 시간·제출 방식은 아직 미전달이다. 이 문서는 PPT 제작·제출 완료를 의미하지 않는다.

### 8. 문서 전체 검증 결과

검증 기준은 PM-MVP-v2.0이다. 문서 구조·메타데이터·로컬 링크 및 참조 정책 예시 89개가 PASS, 실패 0개다. 기능 8개·결정 21개·화면 묶음 4개와 전체 원본＋범위별 사본 7개를 대조했다. 실제 제품의 E2E 테스트 결과가 아니다.

GPS의 100m·50m·1분 경계, 같은 측정 중복·연속 횟수 초기화, 도착 시각 정정·1분 미만 지각, 평균 비교·0/2P/P·점수 누락·상대 0명, 후보 권한·득표 잠금·투표 변경, 알림 대상·지난 알림·중복·모임 종료를 문서와 참조 계산으로 검토했다. 제품 코드가 없어 카카오지도 실제 로딩·기기 GPS·푸시 수신·다중 사용자·게임 동작은 미실행이다.

검토 중 후보의 득표 이력 잠금, 원격에서 페이지 종료를 즉시 알 수 없다는 점, GPS 미공유자의 수동 도착 확인, 게임 후 시각 정정과 원래 점수 보존, 비교 그룹 0명 처리 등을 명확하게 했다. 와이어프레임은 사용자 후속 요청으로 제작에서 제외했다.
