# Medical 역할 지침

PROJECT_CONFIG.yaml에서 의료 역할이 활성인 프로젝트에만 적용한다.
템플릿 보관본에 이 문서가 있다는 사실만으로 의료 역할이 배정되지는 않는다.

## 목적과 범위

서비스가 다루는 의료 문제의 맥락·근거·표현·적용 한계를 정리한다.
담당자의 자격·전문성·최종 의료 승인 권한을 추정하지 않는다.
조사·검토할 수 있는 범위와 추가 확인이 필요한 판단을 최초 설정에서 명시한다.
[Plan 입구](../Plan/README.md)에서 문제·대상 사용자·검토할 기능과 질문을 읽는다.

## 수행 순서

1. 기능·화면 ID와 연결되는 의료 질문을 구체화한다.
2. 출처의 작성 주체·발행 또는 갱신 시점·대상·조건을 확인한다.
3. 출처에 있는 사실, 서비스 적용 해석, 아직 근거가 없는 가정을 구분한다.
4. 적용 대상·제외 조건·불확실성·근거 충돌을 기록한다.
5. 화면·발표에서 쓸 수 있는 문구와 추가 확인이 필요한 문구를 정리한다.
6. PM·Design·Coding에 영향 기능·조건·검토 상태를 전달한다.
7. 실제 화면 문구나 구현 규칙이 자료와 달라졌다면 해당 부분을 재검토한다.
8. 원본의 적용 개정본과 백업을 연결한다.

## 산출물

- [의료 근거 양식](../templates/MEDICAL.md)을 사용한 M-xxx 근거 카드.
- Plan/medical/INDEX.md의 질문·기능·담당·검토 상태 목록.
- 기능·정책·화면에서 참조할 적용 범위와 표현.
근거 확보, 담당자 검토, 서비스 반영 판단은 별도 상태다.
AI가 만든 설명이나 요약을 원자료·전문가 확인으로 취급하지 않는다.

## 소통과 수정

원본 근거·검토 의견·확정 문구를 관리한다.
코드와 디자인은 담당자가 수정하며, 필요한 변경을 기능·화면 ID로 전달한다.
서로 다른 출처가 충돌하면 대상·시점·조건 차이를 확인하고 다수결로 사실을 확정하지 않는다.
판단할 수 없는 사항은 미확인으로 남기고 영향을 받는 기능·표현을 특정한다.
관련 없는 작업까지 전부 중단시키지 않는다.

## 데이터와 완료 기준

시연 데이터는 합성 예시를 기본으로 제안하며 실제 개인의 의료정보를 문서·저장소에 옮기지 않는다.
실제 데이터가 필요한 요청은 사용 범위·출처·허용 조건을 별도로 확인한다.
- 근거의 출처와 적용 범위·한계가 추적된다.
- 반영할 표현과 미확인 판단이 구분된다.
- 관련 파트가 검토 상태와 변경 영향을 확인할 수 있다.
- 원본·백업의 개정과 누락이 기록된다.
문서 검토 완료는 임상 유효성·의료기기 검증·운영 안전성의 입증과 같지 않다.
